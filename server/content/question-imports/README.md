# 题库导入批次

新题**不要直接改** `js/gaoshu_bank.js`。那是 3.68 MB 的单行生成文件，改它会产生巨大 diff、极易冲突，也没法按批次回滚。

新题放在这个目录，一个批次一个 `.json` 文件，服务启动时自动合并进题目池。

## 导入

```bash
cd server
node scripts/import-questions.js <批次.json> --dry-run   # 先看校验结果，不落盘
node scripts/import-questions.js <批次.json>             # 校验通过后写入本目录
```

校验不通过会**整批拒绝**，不会出现「导了一半」的中间状态。写入后**重启服务**生效。

## 回滚

```bash
node scripts/rollback-import.js --list          # 看有哪些批次
node scripts/rollback-import.js <批次文件名>     # 删除该批次
```

删除即回滚，重启后题目从题目池消失。原始题库从未被改动，所以回滚不会伤到它。

## 批次格式

```json
{
  "name": "2026-10-第一批",
  "source": "题目来源与授权说明，必须写清楚",
  "questions": [
    {
      "id": "90001",
      "subject": "高等数学",
      "topic": "函数与极限",
      "difficulty": "基础",
      "type": "选择题",
      "stem": "题干，支持 LaTeX",
      "opts": ["选项A", "选项B", "选项C", "选项D"],
      "ans": "B",
      "solution": "解析"
    },
    {
      "id": "90002",
      "subject": "高等数学",
      "topic": "函数与极限",
      "difficulty": "提高",
      "type": "解答题",
      "stem": "主观题题干",
      "opts": [],
      "ans": "",
      "solution": "参考解答"
    }
  ]
}
```

## 校验规则（任一不过，整批拒绝）

| 规则 | 原因 |
|---|---|
| `id` 为数字串，批内唯一 | 题目池按题号索引 |
| `id` 不与现有题库、已登记缺陷题冲突 | 冲突即拒绝，不静默覆盖 |
| `topic` 必须是已有章节 | 新增章节要走课程配置，不能靠导入绕过 |
| 题干非空 | — |
| 有选项时：≥2 个、无空项、无重复、答案 A–D 且在范围内 | 现有题库里那几道坏题就是栽在这里 |
| 无选项时答案必须为空 | 主观题不该有结构化答案 |
| 单批 ≤ 500 题 | 避免一次导入难以审阅 |

`subject` / `difficulty` / `type` / `solution` 缺失只报警告，不阻断导入。

## 注意

- 批次文件会进版本库，**导入前必须确认题目来源与授权**（见 `docs/team/README.md` 的题库约定）。
- 同一个题号在两个批次里出现时，只有先加载的批次生效，后一个会被判为冲突并整批跳过。
- 不合法的批次不会让服务起不来，但会被记录并在测试中报出来——**不要靠"服务还能跑"来判断导入成功**。
