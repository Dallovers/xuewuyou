# 队友 C：功能与地图交互

本轮主新增功能是**断点续学**，同时把地图与现有学习功能连起来。已有好友、留言、挑战、多人自习、白板不再重复造一套；不恢复已删除的学习工作台。

## 必做任务

| 编号 | 任务 | 完成标准 |
|---|---|---|
| C01 | 现有流程盘点 | 逐一走通地图→课程→章节→练习、白板、错题、复习和报告；以及搭子/留言/竞技/自习。把中断、跳错页、状态不更新的问题提交给对应负责人 |
| C02 | 断点续学前端 | 与 A 确定[接口草案](practice-session-contract.md)，新模块建议放 `js/practice-resume.js`；恢复题序、位置与草稿，刷新/重新登录/第二设备仍可继续；显示清楚恢复来源与冲突 |
| C03 | 真实学习联动 | 保存草稿不等于作答；只在原有提交逻辑确认后更新记录；恢复不重复计分或重复排复习；题目删除时保留可用部分并提示 |
| C04 | 地图入口与状态 | 八个地点用途和入口对应正确，手机不仅有难懂编号；保留地图下方可键盘操作的列表；显示真实记录，未知状态不假画成已掌握/已解锁 |

| C06 | 扩展与回归 | 地点、资源路径、尺寸、锚点与入口配置化；八个地点都验证点击/键盘/手机；新功能优先挂进既有建筑，避免每次加功能都重画整张地图 |

## 断点续学的最小闭环

1. 用户进入一组练习，创建自己的练习会话；固定这组题的顺序。
2. 有节制地保存当前位置与草稿，显示保存状态；本地暂存按账号隔离。
3. 刷新/重新打开后，首页或课程学院出现“继续上次练习”，显示真实课程与完成位置。
4. 进入后恢复上下文，允许明确放弃；没有未完成练习时正常显示开始学习入口。
5. 两个设备同时修改发生版本冲突时保留本地草稿并给选择，不静默覆盖；退出登录清理当前账号可见状态。

不要为续学另建一个“学习工作台”页面。优先复用首页/学院入口和原题目页面，HTML/导航接入由 B 负责。

## 地图接入约定

- 你负责 `js/atlas.js`、`js/atlas-assets.js`、`js/campus-registry.js`。现有逻辑画布：校园 1080×720，课程/章节 1080×680。
- 现有首页八个地点与图书馆保持稳定，先不移动全部落点。确认试放效果后再安排美术修改。
- `study` 目前与学院共用 `college` 类型，接入独立自习馆时新增独立建筑键，不要误替换两个地点。
- 成长中心实际键为 `tower`，不是观测台横幅的 `observatory`。草稿屋键是 `laboratory`，用途是题目草稿，不是已删除工作台。
- 加载失败提供地点按钮/列表回退；图片里不包含功能名、题数、状态、路线或按钮文字。
- 掌握概率为模型估计；地图为学习状态映射，不宣传为已测绘的真实校园。

交付：续学演示、八地点路由/状态清单、图片配置清单、资源失败回退证明、键盘与手机操作记录。样式需要交给 B，后端变更交给 A，避免跨负责人同时改文件。
