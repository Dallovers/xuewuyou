# 队友 C：真实 3D 校园与可移动玩家

你独立负责 3D 场景、人物控制、寻路、碰撞、模型接入、地图操作界面与性能。断点续学和题库已转给 A，不再由你承担。页面的通用 UI 归 B，地图专属 HUD/摇杆/镜头按钮归你。

## 最终行为

人物有站立/行走/跑步动画，可键盘与触屏操作，也可点击合法地面或地点自动走过去；脚贴地，能走桥与阶梯，受墙体、海水和悬崖约束。到达建筑入口后明确提示进入，打开现有课程/资料/自习等功能。保留功能列表直达，用户无需每次走路才能做题。

## 技术方向

建议在现有原生 JS 项目中接入 [Three.js](https://github.com/mrdoob/three.js)，通过独立 ES 模块挂载，不整体迁移框架。导航建议用 [recast-navigation-js](https://github.com/isaac-mason/recast-navigation-js) 构建/查询可行走网格；静态校园可离线生成网格以降低运行负担。若原型证明只需预制网格，可评估 [three-pathfinding](https://github.com/donmccurdy/three-pathfinding)；确定一条运行时路线后锁定依赖，不同时堆两套寻路。

渲染库不会自动提供完整角色控制和碰撞。灰盒阶段就验证墙、桥、楼梯、斜坡、边缘和高度，不能只把人物沿目标点直线补间。是否需要额外物理库由原型结果决定，不默认把小校园做成大型物理游戏。
