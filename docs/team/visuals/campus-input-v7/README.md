# 校园互动输入修复 v7

2026-10-23，用户反馈所有设施无法互动。基于 `bd8dc8a` 本地修复，未推送或部署。

## 复现与原因

从正常界面点击“开始漫游”，点击地点列表步行到图书馆，点击底部开门，再直接按 W：门正常打开，但键盘不再移动人物。此时 `document.activeElement.id` 为 `enter`；原输入逻辑直接忽略按钮/链接上的 E 和移动键，导致像全部互动失效。总览初始状态还把底部互动按钮置为禁用，没有明确的开启入口。

此前室内测试在操作前主动聚焦画布，掩盖了这个问题。本轮新增 `tests/input.cjs`，完整使用实际地点按钮步行和点击，不调用 setPose、canvas.focus 或调试业务入口；修复前首个“点击互动后仍可移动”断言失败。

## 修复

- 总览底部启用“开始漫游 · 开启互动”按钮，E 也可从总览进入漫游。
- 开门/坐下等现场动作、起身和拿书工具操作后恢复场景焦点；已打开业务面板时不抢走表单焦点。
- E / WASD 不再被普通校园按钮焦点阻断；Space 保留按钮的原生激活方式。文本框、选择框和业务窗口继续优先处理输入。
- 完成画质选择后恢复场景控制，无需再点画布。
- 输入回归加入默认 `npm test`，独立入口 `npm run test:input`。

`interiors-validation.json`：原连续室内互动 28 项通过，覆盖教室设备/练习/坐起、图书馆 PDF/书签/阅读计时、自习拿书翻页/坐起/签到、好友/留言/竞技和390px。

`courtyard-validation.json`：原庭院互动 15 项通过，包括喷泉、坐起、资料、实际导航和手机导览。

本轮未重新执行 v6 的所有画质/生命周期专项；旧专项报告保持其原版本归属。测试仍用本机 Edge / D3D11 headless，以及单 CPU 亲和性的 Node 22.14.0。
