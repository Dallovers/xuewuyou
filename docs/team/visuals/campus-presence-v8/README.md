# 校园多人同场 v8

2026-10-23，基于 `2862265` 本地实现。用户进入同一个校园后，能看到其他真实在线账号的人物、昵称和移动。没有用 NPC 或录制轨迹充当在线用户。本轮未推送、远端合并或部署。

## 使用

打开本地 `http://127.0.0.1:4184/js/features/campus-hub/index.html`，右上角“登录加入”复用原登录/注册窗口。两个用户须分别用不同的云端账号，连接同一个后端；本地隔离服务需使用本地测试账号，线上账号库没有接到本地。

有有效账号时自动加入同场。在线人数包含自己；其他用户进入后加载现有角色，显示昵称并同步待机、走、跑、跳与学习中状态。“离开同场”保留当前单人场景；重新加入、断网恢复、关闭页面、隐藏/恢复页面均处理角色和连接清理。同一账号的新窗口接替旧窗口，旧连接断开不会误删新角色。

昵称取已公开的学习搭子名片；未公开名片时生成临时“同学 xxxx”称呼。对外只发临时人物 ID、公开昵称、现有模型枚举和表现状态，不发登录用户名、账号 ID、密码、token、学习记录或好友列表。

## 接入

后端 `server/campus/presence.js` 复用原 `/community` Socket.IO 的身份校验。只在内存保存当前在线状态，客户端10Hz上报，服务端10Hz向参加同场的连接广播；未加入同场的普通社区连接不接收位置。

| 事件 | 方向 | 用途 |
| --- | --- | --- |
| `campus:join` | 客户端 → 服务端，ack | 校验 `campus-hub-v1`、模型枚举、初始状态；返回临时 self 和当前玩家 |
| `campus:pose` | 客户端 → 服务端 | 限频更新有限坐标、朝向、动作、跳跃高度和学习中状态；不信任客户端身份字段 |
| `campus:state` | 服务端 → 已加入的客户端 | 当前在线状态；客户端约110ms插值，不做远程角色物理预测 |
| `campus:leave` / `campus:left` | 双向对应事件 | 离场与清理远端模型 |
| `campus:replaced` / `campus:expired` | 服务端 → 客户端 | 同账号接替、15秒无有效状态超时 |

前端 `src/presence.js` 在原渲染循环更新独立远端人物和昵称，不建第二个 renderer 或 RAF。`createStudentAvatar` 增加可选模型参数和远端动作输入，原本地动作计算保留。角色来自项目已有素材及原许可，没有新增远程模型服务。网络重连丢弃过期 join 回调；隐藏页面离场，恢复时重新加入。现有 Socket.IO namespace 和 auth 的组织方式参考[官方 namespaces 文档](https://socket.io/docs/v4/namespaces/)与[客户端配置](https://socket.io/docs/v4/client-options/)。

服务器每进程最多24个账号。客户端只加载42米内最近4人；390px窄屏最多2人，远处模型释放，昵称20米内显示。角色串行加载，远端行走仍使用当前校园的日光与阴影。人数是同一后端进程、同一世界版本的实际人数，不是网站注册数。

位置只用于呈现，不写存档、作答、积分、自习时长；服务端检查有限数值、世界边界、模型/动作枚举、基本速度包络与上报频率。碰撞继续由各自客户端执行，其他人物没有实体推挤，不能用此协议判定竞技命中或学习奖励。

## 验证

- `presence-validation.json`：12项浏览器检查通过。两个独立浏览器上下文、两个实际注册账号互相加载真实模型；真实按 W 移动和空格跳跃在另一端可见；退出、重新加入、断网与恢复、关闭上下文没有重复或残留人物；390px布局、游客与原登录窗口通过，无未捕获浏览器错误。
- `input-validation.json`：原按钮焦点/E/WASD/画质选择9项通过。
- `interiors-validation.json`：原连续室内28项通过，包括原设备、PDF、阅读计时、实体拿书和社交竞技入口。
- `server/test/campus-presence.test.js`：6项通过，覆盖匿名拒绝、无效输入、双账号同步与非参与者隔离、服务端身份、动作/坐标/频率验证、同账号接替、离场/断开清理及不写学习统计。
- 选跑原校园/社区/自习室服务端回归：29项中28项通过、1项失败。失败是 `community.test.js:53` 掌握模型 `count` 缺失；直接调用学习引擎返回503，提示安装 `services/Setup-Learning.ps1`。用原 `2862265` 的 server.js 在隔离数据中复现同一失败，确认是既有本地学习引擎缺失，没有改动或跳过该测试。原校园8项与自习室7项均通过，原社区7/8通过。
- `npm run check --prefix server` 通过。浏览器测试只允许 loopback 后端，使用本地隔离账号库，不向线上注册或发消息。

复现：启动隔离预览服务后，执行 `npm run test:presence --prefix server`、`npm run test:presence --prefix js/features/campus-hub`。本机 Windows 仍用 D 盘 Node 22.14.0 和单 CPU 亲和性运行测试；没有改变预览服务器亲和性。

## 实拍与边界

`two-players.png`：观察端的实际运行截图，前方角色是另一浏览器中真实按键跳跃的账号，后方是自己；右上角显示同场2人。`mobile-online.png` 为390px实拍，非生成图。

第一版只覆盖公共校园宿主，旧独立预览页没有各自联网。室内读书时仅同步“学习中”，没有同步拿在手里的书或专门坐姿。未新增聊天/语音、多人对打、跨进程人数、Redis同步或其他人物实体碰撞；尚未进行24人负载、实体手机帧率和长期堆内存验收。

上线需同时部署前端和 Node 后端，并让所有客户端通过已有 `js/deploy-config.js` 连接同一个支持 Socket.IO 的后端。GitHub Pages 只托管静态页面；本轮本地成功不等于线上已发布。
