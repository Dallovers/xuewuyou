## 办公本怎么做

安装 Git、Node.js LTS、代码编辑器和浏览器即可。第一批不需要 Blender、Unreal、烘焙工具或 Python 学习引擎；真实业务联调所需后端依赖按仓库说明安装，缺失能力如实记录。

随包的 `接口样例` 含本地 Three.js，可用 Node 启动空房间开发桥接，不需要联网下载纹理或装 3D 软件。它是参考样例，没有自动并入仓库。启动方法见其 README。

开发时一次只加载一个场景；可以使用 1280×720、DPR 上限 1、关闭后处理和高成本阴影的开发画质。保留完整场景入口，不能为了本机流畅覆盖正式素材或降低全项目默认画质。交付时注明实际设备、分辨率和画质；低画质可运行不等于完整效果验收通过。

## 第一批任务：接通一条完整流程

先选 B 的自习入口作为一条纵向流程，用随包空房间实现也可以。业务列表必须来自真实主站；模型未就绪不妨碍完成这一批。

1. **主站进入。** 用户从现有地点/功能入口进入集成预览；保留原有个人自习与多人房间入口，不重命名稳定地点 ID，不顺带重做首页。
2. **打开真实业务。** 在入口附近按 E，或点击可见按钮，打开真实多人房间列表。复用既有导航、账号和业务请求；未登录显示真实登录要求，后端不可用显示错误与重试。不要实现假房间列表，不新增一套账号或同步规则。
3. **打开面板暂停移动。** 清空按键状态、暂停移动与场景快捷键；业务输入框打字不能带动角色。处理指针锁与焦点，不能打开面板后仍向前走。
4. **关闭后恢复。** 关闭面板后恢复场景控制；ESC 优先关闭最上层面板。未获得浏览器要求的用户手势时不要强行恢复指针锁；点击画布可恢复。切后台、失焦后清空按键，避免卡住移动。
5. **返回主站。** 返回原来的业务/地点入口，不跳到无关页面；关闭或卸载旧场景，清理模块拥有的监听、计时器、资源和音频。先明确资源所有权，共享资源不能误删。
6. **反复进入退出。** 连续进入退出至少五次，检查一次 E 只打开一次面板、无重复 RAF 或重复监听、无退出后声音和计时残留。真实正在进行的专注业务如何延续或退出必须沿用业务规则，不能把渲染卸载当作结束服务端学习记录。

需要跨页面返回时优先沿用已有深链；同源业务面板可先复用已验证的 iframe 参考方案，避免立即重构主站。iframe 并不天然解决全局音频、计时和关闭清理，仍需实测。若引入消息桥接，要校验 origin 与 source，并明确消息白名单。

## 公共接口与适配约束

A/B 可挂载模块沿用：

```js
createDistrict({ THREE, openFeature, api, mode })
// 返回 { root, colliders, interactions, update(dt), dispose() }
```

`dt` 单位秒，空间单位米，Y 向上。模块不自建 renderer、不抢相机、不另开 RAF。`api` 只能注入实际存在的业务客户端，不能凭空假定方法。

碰撞为 root 局部坐标 AABB，`half` 是半尺寸；样例只验证 root 无平移/旋转、缩放为 1。第一轮一次显示一个根节点，不把 A/B 任意旋转后继续用原碰撞。确需变换时先实现坐标变换并验证，不能只移动模型。

统一宿主在参考样例中的水平碰撞半径为 0.25 米；A 既有预览曾使用 0.35 米。你需记录、显式配置实际采用值，复查门洞与过道；不要静默改变尺寸后声称通行一致。

业务适配层统一接收 `openFeature(name, options)`：

| name | 目的 | 接入要求 |
| --- | --- | --- |
| `rooms` | 多人自习房间列表 | 参考样例已验证真实主站导航，仍须验收集成后的版本 |
| `study` | 个人自习设置 | 用实际主站入口验证，不自动开始计时 |
| `community` | 社交功能 | 识别 `tab: 'friends' / 'posts'`，核对现有 `WG_Community` 的真实接口 |
| `wenku` | 资料目录 | 保持目录语义；进入 3D 图书馆另走实际 `library3d` 路径 |

不要把 `navTo('community')` 等同于指定好友标签已经生效；不要把打开 `wenku` 等同于进入 3D 图书馆。每条必须实际点击验证。

坐姿相机由宿主负责，B 提供座位朝向和有效起身点；后续先以坐姿视高约 1.15 米、约 0.2 秒过渡、FOV 不变进行标定。暂不要求你在第一批同时完成全体座位相机。

## 文件与 Git 协作

优先把新桥接与宿主代码集中在新目录，例如 `js/features/campus-integration/`；目录是建议，先检查仓库已有结构再确定。主站公共文件只改必要入口与接线。

读取并记录 A/B/C 的交付 SHA。在自己的集成分支引入已认可的依赖版本，保留作者历史和许可证。PR 中列清依赖的 PR/提交及带入的文件；不要混入作者尚未认可的改动，不反向推送他人的分支。

`index.html`、`js/app.js`、`js/campus-registry.js`、`server/server.js` 可能与 C 有冲突。先按合并时基线做最小适配，冲突双方功能都要保留；无法确定时在交付中标明，不删除一边来消除冲突。静态服务仅添加必要白名单，不能开放整个工作区。

缓存版本由总整合在最终合并时统一核对；你的 PR 列出哪些脚本或样式需要更新缓存版本，不提前反复修改队友版本号。D 提交 PR 供审查，不自行合并、部署或覆盖生产。

## 怎么证明完成

交付一份简短记录，把“实测、未测、依赖缺失”分开写：

- main 基线 SHA、A/B/C 依赖 SHA、自己的 HEAD、改动文件和启动命令。
- 一段或几张真实运行记录：进入场景、打开真实功能、关闭恢复、返回主站。
- 登录/未登录、业务失败、输入框打字、ESC、失焦返回、重复进入退出的结果。
- 运行仓库要求的检查；新增验证围绕实际导航和生命周期，不写只重复实现的断言。双账号业务规则仍由 A/B 各自负责，你补查接入后的关键流程。
- 性能只报实际设备和测量条件，不由平均耗时倒推并保证显示 FPS。办公本未完成的完整画质检查明确交总整合复验。

第一批完成标准：一条从主站到场景、真实业务、关闭恢复、返回主站的流程可复跑。第二批再把这条接法用于 A/B/C。模型未完成就用占位模块继续，不等人、不替别人重做模型。

如果某模块接口不符合约定，记录实际返回值、报错与最小复现，交总策划分派原作者修正。紧急最小适配可以放你自己的适配层，避免深入改写三个人的实现。
