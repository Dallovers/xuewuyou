# 队友 A：后端、学习业务与题库

你负责“数据到真实学习结果”的完整链路，包含必要的客户端业务逻辑。断点续学不再由 C 开发，题库工程也不交 B；B 只负责这些功能的界面与样式。

## 任务与完成标准

| 编号 | 工作包 | 可验收交付 |
|---|---|---|
| A01 | 认证与数据可靠性 | 复现首次请求慢；区分服务等待/断网/账号错误，重试有界限；用户明确选择后才进入本地模式。刷新、重启、换账号不丢失或串数据 |
| A02 | 完整断点续学 | 同时实现 API、`js/practice-resume.js` 和现有作答链路接入；恢复题序/位置/草稿，处理 409 冲突；恢复和保存草稿都不重复计分。B 只接 DOM/样式 |
| A03 | 题库工程 | 完成[题库计划](question-bank-plan.md)中的去重、字段校验、来源登记、导入/回滚、难度与章节覆盖报告、首批扩充与后续目标 |
| A04 | 题目分发与组卷 | 统一题号/版本，按科目/知识点/题型/难度筛选与组卷；正常浏览避免整包下载全部题库；题目、素材与解析按需加载，答案的下发时机符合练习/竞技场景 |
| A05 | 业务与地图桥接 | 提供八地点真实学习状态和当前用户地图位置存档；规范见[3D 契约](world-3d-contract.md)。不按每帧上传坐标；位置不可作为积分/完成状态依据 |
| A06 | 多人/互动与能力状态 | 双账号验证自习、好友、留言、竞技、白板；计时/判分/权限由服务器校验。进程、数据库、模型、检索、解析能力分开验证与展示 |
| A07 | 测试、联调与发布 | 独立 PostgreSQL 测试实际通过；浏览器关键流程入库；管理依赖、迁移、CI 和部署/回滚；上线验证跨域、鉴权、实时与资源 |

## 执行顺序

1. 先确认 A01 的阻断问题，同时输出题库审计与接口草案，B/C 不必等服务完成才开发。
2. 实现 A02 和 A05 最小契约，使用隔离测试库验证权限、版本冲突、重启恢复。
3. 修复现有题库字段/计数问题，交付首批新增题；C 做 3D 时你继续推进内容、组卷与分页。
4. 扩容通过验收后，再集中做 A06/A07 全链路回归。不同时另建认证、朋友或房间系统。

## 文件与协作

主责 `server/**`、认证/学习业务脚本、`js/app.js`、`js/api.js`、数据与题库文件、续学模块、内容工具、CI 和部署。全站 HTML/CSS 归 B；地图引擎/地图 HUD 归 C。业务脚本中若混有生成 HTML，先与 B 确认结构契约，由 A 修改模板逻辑、B 提供类名与样式，不两人同时改同一文件。

优先查看 `server/server.js`、`server/lib/store-postgres.js`、`server/study-rooms/index.js`、`server/community/index.js` 与 `js/api.js`。健康接口目前不检查数据库；PostgreSQL 存储已有事务与提交后通知机制，不要破坏。

## 验证与交付

在 `server` 执行 `npm ci`、`npm run check`、`npm test`。未指定隔离测试库时，两个 PostgreSQL 测试会跳过，不能视为通过。将浏览器场景提交到 `tests/e2e/`，不依赖队友电脑上不存在的工作区外脚本。

覆盖：慢网登录；换账号；续学刷新/双设备冲突；提交去重；题库换版后旧题草稿仍可识别；白板保存/导出；双人自习与重连；社交越权；服务重启恢复；题目过滤和答案正确性。

交付 API/状态契约、内容审计与导入记录、测试与发布报告。题目人工校对可由 B/C 在各自模块冻结后交叉抽查，你负责组织与结果登记，不能把审校全部留给前端。
