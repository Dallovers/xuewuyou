# 队友 A：后端与质量

你负责让用户真正完成业务流程，并提供可重复的证据。发布与测试是你的主责；B、C 必须补充各自改动的回归场景。

## 必做任务

| 编号 | 任务 | 完成标准 |
|---|---|---|
| A01 | 登录与后端唤醒 | 区分等待唤醒、网络断开、账号错误、服务异常；重试有上限；只有用户明确选择才进入本地体验。与 B 一起修认证界面，不静默切换数据归属 |
| A02 | 数据与账号隔离 | 练习、错题、复习、草稿、朋友/留言、自习记录刷新和重启后保留；换账号不串数据；失败/冲突不悄悄覆盖新记录；竞争分数与共同计时继续由服务器控制 |
| A03 | 服务能力与故障反馈 | 进程健康、数据库可用、模型可用、检索/解析服务可用分开验证；提供不含密钥的能力状态；未配置功能不假报成功；TXT/MD 的独立能力保留 |
| A04 | 真实多人链路 | 两个独立账号验证邀请、准备、开始、暂停、离开、重连、结束；房主转移、后台标签、多标签去重、服务重启都要检查 |
| A05 | 断点续学接口 | 按[接口草案](practice-session-contract.md)与 C 对齐后实现；只操作当前用户记录，版本冲突明确，重复请求不重复创建；保存草稿不计分 |
| A06 | 自动化与发布 | 后端测试和真实 PostgreSQL 测试通过；把可复现浏览器场景纳入仓库；发布后从公网验证功能与资源，不只检查构建成功 |

## 优先查的代码

- `server/server.js`：认证、CORS、异常响应、启动过程、健康接口。
- `server/lib/store-postgres.js`：事务、并发写、回滚和请求作用域；修改前先理解已有提交后通知机制。
- `server/study-rooms/index.js` 与 `server/community/index.js`：实时权限、计时、统计补写及幂等。
- `js/api.js`：失败分类、重试、账号切换及合并。`js/app.js` 的认证相关改动由 B 合入。
- 现有自动测试位于 `server/test/`；CI 已提供独立 PostgreSQL 服务。

不要用高频轮询或不停访问数据库掩盖服务唤醒问题。不要为本轮 UI 改造另起一套数据库或认证体系。

## 浏览器自动化要覆盖

将实际场景提交到 `tests/e2e/`，用独立测试数据和测试账号，结束后清理。当前工作区已有浏览器检查脚本，但不应假设队友电脑能访问工作区外的脚本路径。

1. 注册/登录→刷新→退出→另一账号登录；慢网和断网期间切换页面。
2. 提交一题→错题/复习/报告更新；重复点击和重复请求不重复计数。
3. 草稿画图→保存→重新打开→导出；另一个账号不能读取。
4. 双账号多人自习全流程及重启恢复。
5. 好友邀请→接受→留言回复→挑战提交与复盘；第三账号越权访问失败。
6. 断点续学刷新、换设备、并发版本冲突与题库更新后的恢复。

## 命令与交付

```powershell
cd server
npm ci
npm run check
npm test
```

本地若没有隔离测试数据库，两个 PostgreSQL 测试会跳过；必须看 CI 数据库专项的实际结果。不使用生产库跑清空、回滚破坏等测试。

交付：问题及修复清单、测试报告、API 契约、外部服务能力表、部署/回滚步骤。没有模型或解析服务凭据时，交付明确的待配置状态，不声称已经真实推理成功。
