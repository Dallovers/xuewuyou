# 3D 校园开放世界评估与场景方案

评估基线：GitHub `Dallovers/xuewuyou` 的 `origin/main`，提交 `6d396b2`。本文把现状、风险和下一轮交付写清楚，避免把灰盒演示误宣传成已经完成的 3D 校园。

## 结论

C 的 `world3d-demo.html` 已经证明了“浏览器里可以走动的 3D 校园”这条技术路线，但目前仍属于 C01 灰盒原型，不能作为《原神》式开放世界或可上线地图验收。建议把目标定义为“有连续道路、高差、地标和学习入口的小型可探索校园”，先做单人可玩闭环，再增加模型、任务和多人表现。

当前完成度如下：

| 能力 | 状态 | 证据与判断 |
|---|---|---|
| Three.js 场景、海岛、道路、八个地点占位 | 已完成（灰盒） | `world3d-demo.html` 使用 Three.js 0.160.0、圆柱岛屿、盒体建筑 |
| WASD、方向键、手机摇杆 | 部分完成 | 有输入处理，但触屏相机旋转和多指缩放尚未实现 |
| 相机、标签、小地图、FPS 统计 | 部分完成 | 有基础 HUD；还没有与主站视觉系统统一 |
| 点击地面/建筑寻路 | 部分完成 | 有二维规则网格 A*，不是基于真实地形的导航网格 |
| 桥、台阶、高度 | 部分完成 | `groundHeight()` 只有两个硬编码矩形，缺少坡道和连续高度 |
| 真实建筑/角色/骨骼动画 | 未完成 | 当前建筑和角色均为 `BoxGeometry` 占位，没有 GLB、骨骼或动画 |
| 建筑进入学习功能 | 未完成 | 没有可靠调用 `StudyAppBridge` 的入口按钮和门口触发器 |
| 位置存档、校园学习状态 | 后端已准备，前端未消费 | `/api/campus/state`、`/api/world/progress` 已有，但 demo 未调用 |
| 主站入口与 2D 回退 | 未完成 | `index.html` 默认仍走 Phaser 2D 地图，3D demo 是独立 HTML |

因此可以把当前版本标成：`C01 已完成；C02 部分完成；C03 部分完成；C04 未完成；C05 未完成；C06 部分完成`。整体适合演示“3D 技术验证”，不适合宣称已经具备开放世界玩法。

## 必须先修的技术问题

### P0：会影响可玩闭环

1. **没有主站接入**。3D 页面没有挂载到首页的地图容器，也没有从建筑门口进入 `bank`、`wenku`、`lab`、`social`、`arena`、`study`、`mistakes`、`report` 的稳定动作。C 应通过已有 `StudyAppBridge.navTo` 或对应的 `openModule` 进入功能，不能复制一套学习逻辑。
2. **导航与高度脱节**。A* 只记录二维 `walk`，`groundHeight()` 只按两个矩形返回高度；桥面没有入口坡道，台阶也不是连续台阶。角色可能突然抬升、走到桥下却被当作桥面，或者沿二维直线跨过视觉障碍。
3. **移动碰撞不可靠**。手动移动只检查目标格是否可走，没有按照角色半径检测建筑边缘、悬崖、桥下空间和快速移动穿墙；路径平滑也只做二维直线检查。
4. **资源失败没有完整回退**。Three.js 通过 CDN 的 ES module 引入，网络失败会在模块执行前停止，页面可能只留下“正在加载 3D 场景”。最终版本必须使用锁定版本的本地构建或 vendor，并在加载超时/模型失败时切回 2D 地图或功能列表。

### P1：会影响上线质量

1. 角色是橙色盒子，没有 idle/walk/run、转向动画和脚底贴地。
2. 建筑是同尺寸彩色盒子，八个地点在空间上有区分，但尚未形成可识别的功能地标。
3. 页面退出时没有统一暂停渲染、移除监听器、释放几何体/材质/纹理的生命周期管理；反复进入可能累积循环和 GPU 资源。
4. `groundPlane` 固定在 `y=0`，点击桥面或台阶时不能可靠拾取真实表面。
5. 手机端只有摇杆，提示中的双指缩放/旋转尚未实现；需要在中档手机上记录持续行走帧率，而不是只看静止截图。

## GitHub 构建建议

当前项目是原生 HTML/JS，建议沿用 Three.js，不为 3D 强行迁移 React。

| 用途 | 建议项目 | 接入方式 |
|---|---|---|
| 渲染、GLB 加载、相机和材质 | [three.js](https://github.com/mrdoob/three.js) | 锁定版本，使用本地构建；`GLTFLoader`、`DRACOLoader` 按需引入 |
| 导航网格、路径和角色群体 | [recast-navigation-js](https://github.com/isaac-mason/recast-navigation-js) | 美术导出静态 navmesh，运行时只查询路径；先做单人，暂不启用 crowd |
| 预制 navmesh 的轻量替代 | [three-pathfinding](https://github.com/donmccurdy/three-pathfinding) | 只在 C 证明无需动态障碍时选用，不能与 Recast 两套并存 |
| 大模型网格拾取/局部碰撞 | [three-mesh-bvh](https://github.com/gkjohnson/three-mesh-bvh) | 只用于射线和局部查询，角色行走仍以 navmesh 为准 |
| GLB 压缩与发布检查 | [glTF-Transform](https://github.com/donmccurdy/glTF-Transform) | 合并前压缩几何、纹理和动画，生成资源清单与体积报告 |

推荐的第一版技术栈是 `Three.js + GLTFLoader + Recast navmesh + glTF-Transform`。不要同时堆入完整物理引擎、多人同步和高精度室内；这些会把地图从可控 demo 变成无法按期验收的工程。

## 地图总设计

地图采用“环形主路 + 中央庭院 + 北高地 + 南侧观景塔”的连续布局。八栋建筑不再平均摆成八宫格，而是形成由学习路径驱动的空间层次：北侧是输入知识，西侧是练习与修复，东侧是社交与竞技，南侧是专注和成长。

```text
                         北 / 高地
              [题目草稿屋] —— [课程学院]
                    \          /
                     \ 中央庭院 /
              [知识图书馆] —— [社交广场]
                  |       桥       |
              [专注营地] —— [好友竞技场]
                   \       /
                [错题修复工坊] —— [成长中心]
                         南 / 观景高塔
```

灰盒阶段可以沿用 C 当前八个地点 ID 和大致坐标，但要把每个门口接到主路，并为桥、坡、台阶留出连续可走宽度。出生点设在中央庭院，安全回退点设在庭院石台；成长中心作为最高处远景地标，保证从多个区域都能看到它。

建议的空间规则：

- 主路宽度 4–5 米，角色与建筑边缘至少留 1.5 米缓冲；支路宽度不低于 3 米。
- 中央庭院是最低风险的导航测试区，放置出生点、状态面板和 2D 回退入口。
- 北侧高地只用一段缓坡连接，不用“瞬移式”高度差；台阶用于短距离展示，但必须有旁侧无障碍坡道。
- 桥面和桥下使用不同高度层，navmesh 中视为两个可行走面；桥头设置明显入口，避免角色从侧面爬上桥。
- 海岸线设置不可行走缓冲带和可见护栏/岩石，点击海面给出“超出校园范围”提示。
- 所有建筑门口放置可交互触发器，只有到达触发范围才显示“进入”，点击远处标签只负责寻路。

## 八个建筑的场景设计

| ID / 建筑 | 远景轮廓 | 地面空间与交互 | 建模重点 |
|---|---|---|---|
| `bank` 课程学院 | 北侧最高的石砖学院，中央台阶、两翼教学楼、低矮钟楼 | 门前有课程公告牌和分流路牌；到门口显示“进入课程地图” | 主体模块化墙体、钟楼和可见入口；不把题目文字焊死在模型上 |
| `wenku` 知识图书馆 | 暖色多层书库，拱窗、蓝灰屋顶、阅读庭院 | 庭院有长椅和资料检索台，状态显示私有资料数 | 书架只做外立面和少量可见室内，夜间窗口暖光作为远景识别 |
| `lab` 题目草稿屋 | 西北侧小型研究工坊，玻璃屋顶、外露黑板和公式符号装饰 | 门口放草稿板，进入后打开题目专属白板 | 玻璃屋顶、工作台、可替换黑板贴图；公式作为材质装饰，不写死业务数据 |
| `social` 社交广场 | 东侧开放连廊、树荫和圆形喷泉，空间最开阔 | 便签留言墙、好友状态柱、多人自习入口 | 连廊柱网、可重复座椅、留言板组件；贴纸内容由页面数据渲染 |
| `arena` 好友竞技场 | 东南侧圆形场地、低矮看台、计分牌塔 | 中央挑战台，门口显示进行中的挑战和“发起竞技” | 可碰撞的环形边界、看台分层、计分牌留动态纹理槽 |
| `study` 专注营地 | 西侧林地里的木平台和小阅读馆，水池与帐篷作为轮廓 | 进入后打开真实多人自习室，周边保持低干扰 | 低面数树木、木平台、柔和灯串；避免大量透明材质导致手机过载 |
| `mistakes` 错题修复工坊 | 西南低地的维修站/工坊，烟囱、分类柜和橙色灯光 | 门口有“待修复数量”牌，进入错题复盘 | 模块化工坊、可替换分类牌、暖光窗口；不做复杂机械物理 |
| `report` 成长中心 | 南侧最高的观景塔/天文台，远处可见，连接环形主路终点 | 观景台显示学习报告、里程碑和路线完成度 | 塔身分段、环形观景台、轻量粒子旗帜；需要低画质远景模型 |

建筑的内部第一版只做“门厅/功能入口”，不要求八栋楼都能自由室内探索。学习功能必须随时可从列表进入，不能因为角色走不到门口而阻塞答题。

## 从灰盒到可玩的开放世界

### 阶段 0：修复当前 demo（C，1–2 个工作日）

- 把单文件拆成 `js/world-3d/`：场景、玩家、导航、建筑、业务桥接、存档、回退。
- 统一 `WORLD_VERSION`、坐标单位、八地点 ID、出生点和门口坐标。
- 用真实坡道连接桥和台阶，导航数据至少带高度层；先完成“出生点到八个门口”的路线回归。
- 增加“进入功能”和“回到 2D 地图”按钮；失败时隐藏 3D 并保留功能列表。
- Three.js 改为锁定版本的本地构建，至少处理加载超时、WebGL 不支持和上下文丢失。

### 阶段 1：灰盒业务闭环（A + C，2–3 个工作日）

- 3D 页面读取 `/api/campus/state`，只显示真实计数；无数据显示空状态，不伪造掌握度。
- 登录后读取 `/api/world/progress`，停留或切场景时节流 `PUT`；处理 409 冲突和 `worldVersion` 变更回出生点。
- 门口动作调用 `StudyAppBridge`，离开学习页时暂停地图循环，返回后恢复。
- 本地未登录允许体验，但明确标注“本地游玩，未云同步”。

### 阶段 2：美术替换与性能（C + 你，3–5 个工作日）

- 先做课程学院、知识图书馆两栋试做模型，确认比例、材质和碰撞，再复制模块化方法到其余六栋。
- 角色交付 GLB、idle/walk/run 三个动作和低面数回退；模型与碰撞体分离。
- 用 glTF-Transform 压缩 GLB 和纹理，第一屏只加载近处模型，远处使用低模/烘焙材质。
- 登记一台笔记本和一台中档手机，桌面目标接近 60 FPS，手机目标稳定至少 30 FPS；达不到就降低阴影、像素比、贴图和绘制次数。

### 阶段 3：内容化探索（A/B/C，后续）

- 先加非战斗任务：到地点、完成一次练习、修复一道错题、和搭子自习、完成一次挑战。
- 再考虑 NPC、天气/昼夜和可收集学习资源；每个系统必须绑定真实学习行为，避免只有装饰。
- 地图多人同屏另立需求，先沿用现有多人自习室，不把多人头像和实时位置混进第一版单人地图。

## 验收清单

发布前必须有可复现证据：

- [ ] 从中央庭院到八个建筑门口都能手动走通、点击寻路走通；路径不跨海、不穿墙、不穿建筑。
- [ ] 桥面、桥下、台阶、坡道的高度连续；角色脚底不悬空，快速移动不穿过薄墙。
- [ ] 到门口才出现“进入”，点击后能打开对应现有功能；远处点击只寻路。
- [ ] 登录用户能读写位置存档；旧 `worldVersion` 能安全回出生点；位置不影响积分、答题和自习时长。
- [ ] 3D 加载失败、WebGL 不可用、上下文丢失、模型/导航失败时能回退到 2D 地图或功能列表。
- [ ] 离开并重新进入地图 10 次没有重复渲染循环、键盘卡住或显存持续增长。
- [ ] 桌面和手机各完成一段完整路线录屏，附 FPS、资源体积、浏览器和设备信息。
- [ ] 真实模型、纹理、字体和开源库都记录来源与许可；概念图只作为参考，不当作最终 3D 资产。

## 边界判断

“类似原神”在本项目中应落在自由探索、连续可达地图、空间地标、角色移动和任务入口这些体验层面。当前团队规模和浏览器部署条件不适合承诺大地图、复杂战斗、八栋完整室内、实时多人世界或全平台 60 FPS。先把八地点的可玩闭环做稳，才有资格继续扩展内容。
