# 擂台现场匹配：两个真人怎么才能坐到一起

## 现象

用户反馈：「竞技场还是没整好，两个人根本匹配不上，根本答不了题。」

上一轮（第十六轮）的验收是 31/31 全绿的，但那个验收在打开浏览器之前替用户做了三件事：
加好友 → 建挑战 → 点「开始作答」。它验的是「**已经有一场开着的挑战**时，两个人能不能坐上去答题」，
而「这场挑战是怎么来的」被脚本跳过了。真实用户只有两个账号和一座竞技场，于是卡在第一步。

## 原因（三条，都只有真人才会踩到）

1. **没有匹配入口。** 挑战只能由好友创建（`POST /api/community/challenges` 要求 `friendship`），
   竞技场里没有「我就想跟站在对面这个人打一局」这条路。两个不认识的账号按 E，
   只回一句「还没有进行中的挑战」，然后什么也不会发生。
2. **就位被 start 锁死。** `duel:enter` 要求挑战里已经有人 `startedAt`，
   而 `startedAt` 是「坐上作答位、面板打开」之后才写的。
   坐不上 → 不能开始 → 更坐不上。邀请阶段上台（很自然的动作）会被回「这场挑战不在进行中」。
3. **服务重启后没有房。** `rooms` 是内存表，重启就没；挑战还在库中。
   两个人都「有挑战、没房间」，按 E 一律被拒。本地开发几乎不会遇到，每次上线都会遇到。

## 改法

- **现场匹配**：`duel:match` 进等待队列，两个人都自己点过就配成一对。配对成功后由
  `community.createLiveChallenge()` 建一场**真的**挑战（五道题、落库、进挑战列表）；
  题库、判分、计分一分都没搬进 presence。**不要求先加学习搭子**——点「匹配」本身就是双向同意。
  位子：先等的人保持自己的位，后来的人去另一边（都站甲位也不会叠在一起）。
- **就位只看 `enterable`**（挑战 active 且没过期），房改懒建：`duel:enter` 时没有房就现建一间。
  `isLive` 仍负责收房，条件是「有人在答 **或** 有人还坐着」。
- **`campus:join` 从库里补房**：同一个 `store.run` 事务里读出「我名下还活着的挑战」，
  逐个 `duelChallenge()`。重启后的第一份真相来自库，不是内存。
- 客户端：`duel.match(seat)` + `duel:matched` 事件。台上没有挑战时按 E 直接进匹配，
  提示从「还没有进行中的挑战」变成「正在匹配对手，另一边也坐上来就开局」。
  配对成功那一刻人不在任何 `await` 里（是对方坐上来触发的），所以面板由 `duel.onChange` 端上来。

## 验证

`_shots/cdp-duel-match.mjs`：两个隔离浏览器、两个**新注册且互不相识**的账号，
**不加好友、不建挑战、不点开始**，全程只走 UI —— **24/24 通过**：

- 开局前甲名下确实一场挑战都没有（不是靠预置数据过关）；
- 甲先上台：没有题、`matching=true`、提示「正在匹配对手」，而不是「没有进行中的挑战」；
- 乙坐下来：两边同时 `phase=answering`、各 5 道题、KaTeX 28 个节点、倒计时 14:59；
- 两边指向**同一场**挑战，甲在 `jia`、乙在 `yi`，对面昵称互相可见；
- 服务端真的建了一条挑战：`active`、5 题、主题「函数与极限」；
- 甲交卷进 `waiting`，乙实时看到「甲同学 · 已交卷」，乙交完双方 `done`，分数 0 / 1（服务端算的）；
- 点「下台」面板关闭、`stance` 清空。

回归与单元测试：

- 好友挑战那条老路 `_shots/cdp-duel-answer.mjs` 仍 **31/31**；
- `server/test/campus-duel.test.js` **7/7**：原 6 条 + 新增「两个陌生人能配成一场真挑战」，
  原第 1 条改写成新规则（**没人 start 也能就位**，并断言是「就位」这一步把房建起来）；
- 服务端全量 220 tests / 204 pass / 12 fail —— 与改动前基线**逐条一致**
  （都是 learning / BKT / OR-Tools 的环境依赖问题，与本次改动无关，已在改动前后各跑一遍对照）。

## 明确没做

- 不做段位/积分匹配：只有"先来后到"的队列，没有 ELO、没有跨房间组队。
- 独立入口页 `js/features/arena/index.html` 仍是「读列表 / 发起 / 开始」那套，没有匹配按钮；
  现场匹配只在整合版 `campus-hub` 的作答位上。
- 不替用户自动加好友：匹配出来的挑战在列表里能看到对手昵称，但两人仍不是学习搭子。
- 队列不落库：进程重启就清空，等的人要重新点一次（现场排队本来就该是易失的）。
